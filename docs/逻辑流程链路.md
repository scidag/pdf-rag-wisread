## 1. 认证与鉴权链路

### 1.1 注册 / 登录 / 刷新 / 登出

入口：[AuthController.java](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/controller/AuthController.java)，核心逻辑在 [AuthService.java](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/service/AuthService.java)。

#### 注册 `POST /api/v1/auth/register`
```
AuthService.register(request)
  ├─ 校验 username / email 不重复（重复 → 409 CONFLICT）
  ├─ BCrypt 加密密码 → 写入 user 表
  └─ issueTokens(user, null, null)
        ├─ JwtService.createAccessToken(userId, username)   // 短期，返回给前端
        ├─ JwtService.createRefreshToken(userId, username)  // 长期
        ├─ refresh token 做 SHA-256 → 存 user_session（只存哈希，不存明文）
        └─ 返回 AuthResponse{accessToken, refreshToken, expiresIn, user}
```
> 注册不记录 device / ipAddress；登录与刷新会记录。

#### 登录 `POST /api/v1/auth/login`
```
AuthService.login(request, device, ipAddress)
  ├─ UserRepository.findByEmail(email)  → 不存在 → 401 "invalid credentials"
  ├─ BCrypt.matches(raw, hash)          → 不匹配 → 401 "invalid credentials"
  └─ issueTokens(user, device, ipAddress)   // 同上
```
后端通过 Cookie `wisread_refresh`（HttpOnly，路径 `/api/v1/auth/refresh`）下发 refresh token。

#### 刷新 `POST /api/v1/auth/refresh`
```
AuthService.refresh(cookie中的refreshToken, device, ip)
  ├─ 空/blank → 401 "missing refresh token"
  ├─ sha256(refreshToken) → UserSessionRepository.findByRefreshTokenHashAndExpiresAtAfter(hash, now)
  │     未命中或已过期 → 401 "invalid refresh token"
  ├─ 生成新的 refreshToken（旋转 refresh token，旧哈希被覆盖）
  ├─ 更新 session 的 hash / device / ip / expiresAt
  └─ 返回新 accessToken + 新 refreshToken
```
> **Refresh Token 旋转**：每次刷新都换发新的 refresh token，防止重放。

#### 登出 `POST /api/v1/auth/logout`
```
AuthService.logout(refreshToken)
  └─ 根据 hash 找到 session → deleteById（删除会话记录）
```

### 1.2 JWT 鉴权过滤器（每个受保护接口）

实现：[JwtAuthenticationFilter.java](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/security/JwtAuthenticationFilter.java)，继承 `OncePerRequestFilter`。

```
请求到达
  └─ JwtAuthenticationFilter.doFilterInternal
        ├─ 读取 Authorization 头
        ├─ 若以 "Bearer " 开头：
        │     ├─ JwtService.parseUserId(token)
        │     ├─ 成功 → 构造 UsernamePasswordAuthenticationToken(userId, null, [])
        │     │        写入 SecurityContextHolder
        │     └─ 异常 → SecurityContextHolder.clearContext()（不抛错，继续放行）
        └─ filterChain.doFilter(request, response)
              ↓
        SecurityConfig 决定该路径是否需要认证
              ├─ /auth/register、/auth/login、/auth/refresh、健康检查 → 放行
              └─ 其余路径无认证 → 401
```

控制器里通过 `Authentication.getPrincipal()` 拿到 `userId`（Long），后续所有查询都带这个 `userId` 过滤。

### 1.3 前端 Token 策略

实现：[lib/auth-store.ts](file:///e:/AI%20code/智阅/frontend/lib/auth-store.ts)、[lib/api.ts](file:///e:/AI%20code/智阅/frontend/lib/api.ts)。

```
- accessToken 只存内存变量（module-level let），绝不写 localStorage
- 刷新页面 → 内存丢失 → workspace 页挂载时调 restoreSession()
    → POST /auth/refresh（带 HttpOnly Cookie）→ 取回新 accessToken 写回内存
- apiFetch 拦截 401 → 自动 restoreSession() → 用新 token 重试一次原请求
- credentials: "include" 确保 Cookie 自动携带
```

## 2. 文档上传与索引链路（异步）

### 2.1 同步上传阶段

入口：`POST /api/v1/documents`（multipart）→ [DocumentController](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/controller/DocumentController.java) → [DocumentService.upload()](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/service/DocumentService.java)。

```
DocumentService.upload(userId, file)
  ├─ file 为空                       → 400 "file is required"
  ├─ file.size > 100MB (100*1024*1024) → 413 "file exceeds 100MB limit"
  ├─ 读取 bytes 失败                 → 422 "failed to read uploaded file"
  ├─ isPdf(bytes)：校验前 4 字节 == "%PDF"  → 不匹配 → 415 "only PDF files are supported"
  ├─ countByUserId(userId) >= 5      → 400 "user document limit of 5 reached"
  │
  ├─ fileKey = userId + "/" + UUID.randomUUID() + ".pdf"
  ├─ MinioStorageService.putObject(fileKey, bytes, "application/pdf")
  │
  ├─ 创建 Document{userId, filename, fileKey, fileSize, status="UPLOADED"}
  ├─ 创建 DocumentJob{documentId, status="PENDING"}
  ├─ documentProcessingService.processDocument(documentId, userId)   // @Async 立即返回
  └─ 返回 DocumentResponse（此时 status 仍是 UPLOADED）
```

> 关键约束：`MAX_FILE_SIZE = 100MB`、`MAX_DOCUMENTS_PER_USER = 5`、PDF 魔数校验。

### 2.2 异步处理阶段

实现：[DocumentProcessingService.processDocument()](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/service/DocumentProcessingService.java)，标注 `@Async("documentTaskExecutor")`，线程池由 [AsyncConfig](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/config/AsyncConfig.java) 提供。

```
processInternal(documentId, userId)
  ├─ 取 Document、DocumentJob（按 userId 过滤，越权 → 404）
  │
  ├─ 状态推进：Document.status = PROCESSING
  │            DocumentJob.status = RUNNING, startedAt = now
  │
  ├─ ① 取原文：MinioStorageService.getObject(fileKey) → byte[]
  ├─ ② 解析：PdfParsingService.extractPages(pdfBytes) → List<PageText>
  │     若所有页 text 都为空 → 422 "scanned or empty PDF is not supported"
  ├─ ③ 切块：逐页 ChunkingService.splitPage(page, nextChunkIndex)
  │     累加 tokenCount，若 totalTokens > 500_000 → 422 "document exceeds 500000 token limit"
  ├─ ④ 向量化：EmbeddingService.embed(texts) → List<float[]>
  ├─ ⑤ 入库：VectorIndexingService.saveChunks(documentId, userId, chunks, embeddings, embeddingModelVersion)
  │           写入 pgvector，记录 embedding_model_version
  │
  ├─ 成功收尾：
  │     Document.{pageCount, tokenCount, embeddingModelVersion, status="READY", errorMessage=null}
  │     DocumentJob.{status="SUCCEEDED", finishedAt=now}
  │
  └─ 异常 → handleFailure(document, job, exception)
```

### 2.3 失败重试机制

```
handleFailure(document, job, exception)
  ├─ document.retryCount < 1   （即首次失败）
  │     ├─ VectorIndexingService.deleteByDocumentId(documentId)  // 清理已写入的向量
  │     ├─ Document.retryCount += 1, status = "UPLOADED", errorMessage = ...
  │     ├─ DocumentJob.attempt += 1, status = "PENDING", 清空 startedAt/finishedAt
  │     └─ 递归调用 processInternal(documentId, userId)   // 立即重试一次
  │
  └─ retryCount >= 1 （重试仍失败）
        ├─ Document.status = "FAILED", errorMessage = ...
        └─ DocumentJob.status = "FAILED", finishedAt = now, errorMessage = ...
```

### 2.4 状态机

**Document.status**
```
UPLOADED ──(异步任务启动)──▶ PROCESSING ──成功──▶ READY
   ▲                            │
   │                            失败(retryCount<1)
   └────────────────────────────┘
                                │
                                失败(retryCount>=1)
                                ▼
                              FAILED
```
> 删除时由 `DocumentService.delete()` 物理删除（删 MinIO 对象 + 删 DB 行），AGENT.md 中提到的 `DELETED` 状态当前代码未实际使用。

**DocumentJob.status**：`PENDING → RUNNING → SUCCEEDED / FAILED`（重试时回退到 PENDING）。

### 2.5 前端轮询

```
UploadPanel 上传成功
  └─ DocumentList 每 2 秒轮询 GET /documents/{id}/status
       ├─ status ∈ {READY, FAILED} → 停止轮询
       └─ 其他 → 继续
```

## 3. RAG 流式问答链路（SSE）

### 3.1 入口与异步封装

入口：`POST /api/v1/conversations/{conversationId}/messages`，`produces = text/event-stream`。

[ConversationController.chat()](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/controller/ConversationController.java) → [ChatService.ask()](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/service/ChatService.java)：

```java
public SseEmitter ask(Long userId, Long conversationId, ChatRequest request) {
    SseEmitter emitter = new SseEmitter(120_000L);   // 120s 超时
    executor.execute(() -> processAsk(userId, conversationId, request, emitter));  // 异步处理
    return emitter;   // 立即返回，流式写入由后台线程完成
}
```

### 3.2 processAsk 主流程

```
processAsk(userId, conversationId, request, emitter)
  │
  ├─ ① 鉴权 + 取上下文（均按 userId 过滤，越权 → 404）
  │     ConversationRepository.findByUserIdAndId(userId, conversationId)
  │     DocumentRepository.findByUserIdAndId(userId, conversation.documentId)
  │
  ├─ ② 持久化用户消息
  │     Message{conversationId, role="user", content, status="COMPLETED"}
  │
  ├─ ③ 取历史对话（最近 10 条，按时间正序）
  │     findTop10ByConversationIdOrderByCreatedAtDesc(conversationId).reversed()
  │
  ├─ ④ 查询改写
  │     QueryRewriteService.rewrite(content, history) → query
  │
  ├─ ⑤ 问题向量化
  │     EmbeddingService.embed(List.of(query)).get(0) → float[] queryEmbedding
  │
  ├─ ⑥ 向量召回 Top 10
  │     VectorIndexingService.searchWithContent(userId, documentId, queryEmbedding, 10)
  │       → List<ChunkSearchResult> candidates
  │
  ├─ ⑦ 重排取 Top 3
  │     RerankService.rerank(query, candidates) → chunks
  │
  ├─ ⑧ 相似度兜底
  │     if chunks.isEmpty() || chunks.get(0).distance() > 0.65:
  │         sendNoAnswer(conversationId, emitter)   // 见 3.4
  │         return
  │
  ├─ ⑨ 构建 Prompt
  │     buildPrompt(query, chunks, history)
  │       SystemMessage:
  │         "你只能根据提供的文档内容回答。"
  │         "如果文档没有相关信息，回答'文档中没有找到相关信息'。"
  │         "引用必须使用系统提供的编号 [1]..[3]。"
  │         "禁止自行生成不存在的编号。"
  │         + 每个块: [i] {content} (第 {pageStart} 页)
  │       + 历史消息（UserMessage / AssistantMessage）
  │       + 当前问题 UserMessage
  │
  ├─ ⑩ 流式生成
  │     chatModel.stream(prompt).subscribe(
  │       onNext  → token 非空时：answer.append(token); 发送 SSE event name="delta" data={content:token}
  │       onError → emitter.completeWithError
  │       onComplete → completeAnswer(conversation, chunks, answer, emitter)
  │     )
  │
  └─ 任意异常 → emitter.completeWithError(exception)
```

> 关键阈值：`DISTANCE_THRESHOLD = 0.65`（等价相似度 0.35）；召回 10 → 重排 3。

### 3.3 完成阶段 completeAnswer

```
completeAnswer(conversation, chunks, answer, emitter)
  ├─ 持久化 assistant 消息
  │     Message{conversationId, role="assistant", content=answer, status="COMPLETED"}
  │
  ├─ 引用解析与校验
  │     CitationParsingService.parseAndValidate(answer, chunks)
  │       ├─ 正则 \[(\d+)\] 提取 answer 中所有 [n] 编号（LinkedHashSet 保序去重）
  │       ├─ 遍历 retrievedChunks（marker = i+1）：
  │       │     若 markers 包含 marker → 构造 SourceResponse{marker, chunkId, pageStart, pageEnd, snippet}
  │       │     snippet = chunk.content() 前 120 字符 + "..."（SNIPPET_LENGTH=120）
  │       └─ 模型瞎编的编号（不在 [1]..[3] 内）自动被丢弃
  │
  ├─ 逐条写入 answer_source 表（relevanceScore=1.0f）
  ├─ 更新 conversation.updatedAt
  │
  └─ 发送 SSE event name="done" data={content:answer, sources}
     emitter.complete()
```

### 3.4 无答案兜底 sendNoAnswer

```
sendNoAnswer(conversationId, emitter)
  ├─ answer = "文档中没有找到相关信息"
  ├─ 持久化 assistant 消息（同上）
  └─ SSE event name="done" data={content:answer, sources:[]}   // 注意：也是 done 事件，sources 为空
     emitter.complete()
```

> 触发条件：`chunks.isEmpty()` 或 `chunks.get(0).distance() > 0.65`。

### 3.5 SSE 事件协议

| 事件名 | data | 时机 |
|---|---|---|
| `delta` | `{"content": "<token>"}` | 每生成一个 token |
| `done` | `{"content": "<完整答案>", "sources": [...]}` | 生成完成或命中兜底 |

前端 [lib/sse.ts](file:///e:/AI%20code/智阅/frontend/lib/sse.ts) 的 `streamChat` 用 `ReadableStream` reader 解析，回调 `onDelta(token)` / `onDone(payload)`。

### 3.6 引用编号约束闭环

```
后端 Prompt 注入 [1][2][3] 编号
        ↓
模型生成 "根据 [1] ... [3] ..."
        ↓
CitationParsingService 用正则提取编号
        ↓
只保留 1..chunks.size() 范围内的合法编号
        ↓
非法编号（模型幻觉）被静默丢弃
        ↓
前端 SourceCard 展示 {编号, 页码, 原文片段}
```

## 4. 用户隔离与安全约定

贯穿所有数据访问层，是本项目最核心的约束：

| 维度 | 实现 |
|---|---|
| 查询带 userId | `DocumentRepository.findByUserIdAndId`、`ConversationRepository.findByUserIdAndId`、`VectorIndexingService.searchWithContent(userId, ...)` 等全部带 userId |
| 越权响应 | 统一抛 `ApiException(404, "... not found")`，**不返回 403**（避免泄露资源存在性） |
| 异常处理 | [GlobalExceptionHandler](file:///e:/AI%20code/智阅/backend/src/main/java/com/wisread/exception/GlobalExceptionHandler.java) 统一转 JSON `{code, message}` |
| refresh token 存储 | 只存 SHA-256 哈希到 `user_session`，明文不下库 |
| access token 前端存储 | 仅内存，不写 localStorage |
